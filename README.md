## Focus

This repository explores defensive questions around AI-assisted development and LLM applications:

- prompt-injection resistance
- insecure code generated by coding assistants
- unsafe tool invocation patterns
- secret exposure and hard-coded credentials
- risky shell/process execution
- weak cryptographic choices
- unsafe deserialization and file handling
- dependency and supply-chain review

The lab is intentionally lightweight and reproducible. It does not depend on any private model API key.

## Repository structure

```text
.
├── evals/                   # security evaluation cases
├── scanner/                 # static checks for AI-generated code
├── checklists/              # review methodology
├── samples/                 # safe intentionally-insecure snippets
└── tests/                   # unit tests for the scanner
```

## Security evaluation themes

| Area | Question |
|---|---|
| Prompt injection | Can untrusted content override system/user intent? |
| Code generation | Does generated code introduce common security flaws? |
| Secrets | Does the workflow leak or hard-code sensitive values? |
| Tool use | Can an agent execute commands or access files too broadly? |
| Dependencies | Are generated dependency choices outdated or risky? |
| Output handling | Is generated output validated before execution/use? |

## Quick start

Scan the included safe sample snippets:

```bash
python -m scanner.scan samples
```

Run tests:

```bash
python -m unittest discover -s tests -v
```

## What the scanner checks

The current prototype flags a small set of explainable patterns:

- `shell=True` in subprocess calls
- direct `os.system(...)`
- `eval(...)` and `exec(...)`
- obvious hard-coded secret-like assignments
- weak hashes such as MD5/SHA-1 when used directly
- unsafe YAML loading patterns

This is a learning tool, not a replacement for Semgrep, Bandit, CodeQL or professional SAST.
